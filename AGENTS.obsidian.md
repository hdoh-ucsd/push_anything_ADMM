# Obsidian Vault Instructions for Coding Agents

This file is a template for the root of the research Obsidian vault. Review it
against the actual vault before installing it there.

## Preservation

- Never delete notes or attachments automatically.
- Preserve `[[wikilinks]]`, embeds, headings used by links, block references,
  aliases, tags, and attachment paths.
- Preserve YAML/frontmatter keys and values unless a metadata migration is
  explicitly approved.
- Move uncertain duplicates, stale notes, and attachments with unclear
  ownership to `_review/`; do not merge them based only on similar titles.
- Do not silently rewrite research conclusions, experimental observations, or
  the author's interpretation.

## Knowledge organization

- Prefer links and Maps of Content (MOCs) over deep folder nesting.
- Create a MOC only when existing notes form a useful cluster; do not generate
  empty taxonomies.
- Keep source claims, direct quotations, personal interpretation, experimental
  evidence, and original ideas visibly distinct.
- Link paper notes to projects and concepts only when the relationship is
  supported by the note contents.
- Link people to relevant labs, papers, programs, and projects without inventing
  relationships.
- Keep research ideas connected to their source or mark them explicitly as
  original ideas when no source exists.

## Repository links

- Keep the vault independently readable and the code repository independently
  reproducible.
- Prefer stable repository URLs, commit identifiers, experiment IDs, and config
  paths over machine-specific absolute paths.
- A result note should identify the experiment command/config, code revision,
  output artifact, interpretation, and related paper where known.
