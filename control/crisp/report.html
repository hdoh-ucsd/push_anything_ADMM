Retracted

An earlier version of this page reported a clean escape-threshold bracket — q=290 parks at 0.0000 m, q=310 reaches 0.1490 m, against a predicted q*=300.8. That was measured with the wrong encoding. Under the reference formulation the transition is non-monotone: q=250 escapes and q=310 does not. The barrier is real — at q=150 and q=290 the box does not move at all and the solver still reports success — but it is a scale, not a switch.

Two further facts change how the paper reads. Its push-box benchmark goal is [3cos θ, 3sin θ, θ] with θ = 12·2π/18, so the benchmark demands 3 m of travel and 240° of rotation — it never tests pure rotation. And the shipped main() solves one of the 18 targets: the sweep loop has been deleted, leaving orphaned indentation and a stray brace, so the repository does not ship the code that produces Table II's 100% success rate.

Model comparison

B-B deletes the sampler by construction

Our stack sends contact geometry into the planner as sampled witness points on a mesh. B-B sends it as four inequalities on a decision variable. That single change is what makes the whole sampler-and-witness apparatus unnecessary.

Failure mode · provable

Rotation is invisible to a naive guess

Yaw enters the dynamics as θ̇ = k_rot (c_x f_y − c_y f_x) — a product of two variables that both start at zero. So at the all-zero guess the rotation row of the Jacobian is identically zero while translation is not:

d(ṡ)/du at the all-zero knot

[ 0  0  0       0.2216  0       0.2216 ]   translation — first order
[ 0  0  0.2216  0       0.2216  0      ]
[ 0  0  0       0       0       0      ]   rotation — identically zero

Translation needs only a force; rotation needs a force and a moment arm. A pure-rotation goal therefore has no first-order descent direction, and the solver terminates at a genuine stationary point — reporting success having moved nothing, at every terminal weight tested (×10, ×100, ×1000). This is the one finding the reference audit left untouched: re-measured under the corrected formulation it is unchanged to four decimals, as it must be, since it is a property of dynamics both implementations share.

The audit did narrow it. The reference benchmark always couples rotation with travel, so it never enters this regime — once translation is present λ leaves zero, the moment arm acquires a gradient, and rotation is reachable: at the reference configuration this port turns the box 3.69 rad of a 4.19 rad goal.

Why our canonical task never noticed

pushing sets goal_yaw: 0, so it never touches the rotation channel. Any orientation-carrying task — the T, the jack, most of Fig 8 — lands here immediately. In receding-horizon use the cold start only bites on the first tick, but a box at rest with a do-nothing plan never generates the motion that would warm-start the next one.

Failure mode · calibration

The all-zero guess can silently do nothing

The all-zero point is feasible: no force, no motion, every complementarity product zero. Escaping it costs linearised face-gate violation, because at λ = 0 the gate's own contact-point gradient ∂/∂c_x[λ₂(c_x+a)] = λ₂ is itself zero. Per knot and per unit force the trade is μ₀·a against q·d·dt·k_trans, which is knot-count independent — so the origin is escapable only when

Well below the threshold the solver returns a feasible, converged, useless plan and calls it success — the same outcome the paper criticises IPOPT for in its own transport example. The transition itself is not sharp (see the retraction above), but the danger is unchanged: silence looks like success. min_terminal_weight() exposes the scale and weights auto-size to 10× it.

Correcting the constants and the encoding carried the box from 2.633 m to 2.9592 m of the 3 m goal — most of the gap closed. What did not close is feasibility: 7.53e−5 against the reference's own 1e−6 bar.

The failure is scale-dependent. On our own box the trade is escapable — q ×1000 delivers a perfect trajectory and 1e−12 feasibility. At the reference's 3 m scale nothing tested delivers both, and the sweep is not even monotone: ×100 is worse than ×10 on both axes. Sweeping r_lambda across two decades still changes nothing, so the binding trade is against the ℓ₁ penalty on the complementarity residual, not the control cost.

The paper predicts this exactly

Remark 10 warns that first-order QP solvers give “insufficient solution quality … [that] may hurt motion planning”, and the source confirms CRISP runs PIQP. This port uses OSQP — precisely the first-order ADMM solver that remark warns against — and under the now-faithful formulation it needs roughly 4× the iterations and stops converging at short horizons on a problem the reference solves routinely. Q and R are no longer guesses, so the weighting explanation is spent. The solver explanation is not.

Integration

What executing a plan would actually require

The executor layer transfers cleanly. B-B plans a contact point on the box surface; a real pusher sits one radius outside it — the same offset our sampler calls sampling_setback. to_execution_plan() does that conversion and emits exactly the p_ee_desired and lambda_des that OperationalSpaceController.compute_torque already accepts.

What does not transfer is everything the model leaves out. B-B constrains the contact point c_k only through the face gates and the box bounds — nothing links c_k to c_{k+1}, so a plan may teleport the pusher between faces at no modelled cost. Our entire reposition apparatus — the PWL tracker, finished_reposition_cost, the c3/free mode switch and its hysteresis — exists to pay that exact bill. B-B does not remove the problem; it stops accounting for it. Add to that no pusher friction, no arm or reachability, no velocities, and no out-of-plane freedom.

These got worse under the reference-faithful encoding — previously 166.8 / 443.5 / 1044.7 ms, all converging. Caching the Jacobian sparsity changed nothing, so the cost is iteration count, not assembly. The paper's C++ implementation solves the harder push-T problem — eight faces, 29 states — at 80 ms per MPC cycle, so a real-time B-B is plausible; nothing in this Python implementation demonstrates it.

Verdict

A planner for where to push, not a replacement

For the canonical box task B-B is accurate, converges in 15 iterations, and needs no sampler, no witness table and no mode switch. But that case — one face, no rotation — is the whole of what works here, and the rotation limit is provable rather than tunable. The defensible use is as an upstream contact-sequence proposer feeding our existing OSC, replacing the sampler and mode switch rather than the LCS executor.

Two things settle whether that is worth pursuing, in this order:

  1. Re-run against an interior-point inner QP — PIQP, or Drake's Clarabel/SCS. This is no longer a hypothesis: the reference uses PIQP, and our OSQP build needs ~4× the iterations on the identical formulation. Until the inner solver is cleared, none of the failure modes above — except the rotation Jacobian, which is formulation-independent — is safely attributable to B-B itself.
  2. Decide what pays for repositioning. A contact-point rate constraint is the minimal honest addition — and it is off-reference for both lineages, so it needs a deliberate call rather than a quiet patch.
