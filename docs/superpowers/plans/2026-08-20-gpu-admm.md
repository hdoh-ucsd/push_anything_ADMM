# GPU-Accelerated ADMM (C3+) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the C3+ ADMM inner loop (85% of wall time per `memory/project_admm_perf_psd_check_2026-08-20.md`) onto the RTX 5070 Ti as a *batched, on-device* solver — batching over the 5–6 per-tick samples, keeping all iterates on-device — behind an opt-in `PORT_GPU_ADMM=1` gate that is byte-identical when unset.

**Design basis:** cuNRTO (Wang, Taj Abdul, Theodorou; arXiv:2603.02642; RSS 2026), sole basis by user decision 2026-08-20. cuOSQP (arXiv:1912.04263) was considered and dropped. Project page <https://cunrto.github.io/> checked 2026-08-21: **no code release**, so everything below derives from the paper plus its Supplementary Material (pp. 11–15 of the arXiv PDF, SM §VII–§XI).

**Tech Stack:** PyTorch ≥ 2.7, CUDA 12.8 wheels (RTX 5070 Ti is Blackwell, compute capability **12.0 / sm_120** — verified via `nvidia-smi`; older wheels will not run). float64 on device. `torch.linalg.cholesky` + `torch.cholesky_solve`, batched over samples. NumPy stays the interchange format at the module boundary.

**Evaluation convention:** every run in this plan goes through `scripts/gpu/run_gate.sh`, which pins the single canonical seed 0. The seed is held **fixed** while the configuration varies. This is not a seed sweep (`feedback_no_statistical_evaluation`); it is the same-protocol baseline discipline of `feedback_baseline_provenance`.

## Part 1 — What the paper actually prescribes

cuNRTO is a bi-level solver: an outer **successive-linearization (SL)** loop on the host CPU, and an inner **ADMM/DR** loop on the GPU. Its speedups (25.9x on the Franka; 139.6x max) come from six specific mechanisms, not from "using a GPU":

| # | Mechanism | Where in the paper | What it actually says |
|---|-----------|-------------------|----------------------|
| P1 | **Whole inner loop on-device** | §IV-B, Fig. 5, Remark 1 | "eliminates CPU-GPU data transfer bottlenecks by executing the entire inner ADMM loop on the GPU." Constants upload **once per outer iteration**; the inner loop never touches the host. |
| P2 | **Batch the independent blocks** | §IV-B.2, Fig. 4 | Each SOC constraint block is handled by one warp; projections are "separable across constraints" and scale "linearly with n_g … near-ideal parallel efficiency." |
| P3 | **Factor once, reuse** | SM §VIII-B | "Within one SL iteration, **K_KKT is constant, and only the RHS changes, enabling factorization reuse**." Factor with cuDSS once, reuse triangular solves across all inner iterations. |
| P4 | **Precompute operator chains** | SM §IX-B, eq. (43)–(44) | Block-2 collapses to `k_v = q + M*k_v_prev + M_bar*nu` with `M = (Q_v + sum_j rho*A_j'A_j)^-1` built **once per outer iteration** and reused by every inner iteration. |
| P5 | **Closed-form, elementwise projections** | §III-B, SM §VIII-C eq. (34) | The cone projection is a 3-case closed form computed by a custom kernel, "bandwidth-bound," one warp per constraint. |
| P6 | **Loose inner tolerances + warm start** | SM Tables V, VII, VIII | PCG `tol` in {0.01, 0.05}, ADMM iters 40–80, `warm start: true`. They deliberately solve inner systems to low accuracy. |

**What cuNRTO does NOT claim, and we must not import:** the 139.6x is versus **MOSEK interior-point on CPU** at 40–80 ADMM iterations with thousands of SOC constraints — a comparison against a *different algorithm class* on a *much larger problem*. Our CPU baseline is OSQP (first-order, same class) at **3** ADMM iterations. The architecture transfers; the number does not.

## Part 2 — How each prescription maps onto our port

Our stack has **three** nested levels where cuNRTO has two:

```
cuNRTO                             push_anything_ADMM
------                             ------------------
outer SL loop      (host CPU)  <-> control tick: Drake LCS linearization (host CPU, stays)
inner ADMM/DR loop (device)    <-> C3+ ADMM loop, admm_iter = 3          (target: device)
  Block-1: one KKT solve       <->   z-update: a full QP solve via OSQP  (target: device)
                                       '- OSQP's own ADMM, ~100-2000 iters  <- extra level
```

| # | cuNRTO mechanism | Our analogue | Task |
|---|-----------------|--------------|------|
| P1 | Inner loop fully on-device | All 3 C3+ iterations plus every inner QP iteration run on-device; only `u_seq`/`x_seq` return | T8, T11 |
| P2 | Batch independent blocks | **Batch the 5–6 per-tick samples** (`num_additional_samples_c3: 5` plus current, or `_repos: 4` plus current). Same shapes, different data — the natural batch axis | T8, T11 |
| P3 | Factor once, reuse | Factor the reduced KKT **once per C3+ ADMM iteration**, reused across all inner OSQP iterations (see C2 — *not* once per tick) | T7 |
| P4 | Precompute operators per outer iter | Assemble `P`, `q_ref`, `C_eq`, box rows **once per tick** in a shared pure function; upload once | T5, T8 |
| P5 | Closed-form elementwise projection | `_project_C3Plus` (Bui eq. 12) is already `np.where` — a 4-line torch transcription. **Cheaper than cuNRTO's SOC projection**: no norms, no cone cases | T6 |
| P6 | Loose tolerance + warm start | **Adopt the warm start** (thread `x`/`z`/`y` across C3+ iterations). **Reject the loose tolerance** — conformance requires matching OSQP's `eps=1e-5`, not undercutting it | T7 |

## Part 3 — Verified codebase facts (read at HEAD, 2026-08-21)

Four corrections to earlier drafts. Each was verified by reading source, not inferred.

**C1 — The projection symbol and its rule.** There is no `_project_componentwise`. The real symbol is `C3Solver._project_C3Plus` (`control/admm_solver.py:1035`, staticmethod), with module-level test alias `project_C3Plus_eq12` (`:2968`). Its rule is a **threshold** test, not a nearest-point test:

```python
sqrt_ratio = sqrt(u_lambda / u_eta)
cond1 = (eta >= 0.0) & (eta >= sqrt_ratio * lam)   # case 1 -> (0, eta)
cond2 = (lam >= 0.0) & (eta <  sqrt_ratio * lam)   # case 2 -> (lam, 0)
delta_lam = np.where(cond2, lam, 0.0)              # else    -> (0, 0)
delta_eta = np.where(cond1, eta, 0.0)
```

It is already vectorized NumPy and **elementwise-separable** — precisely what makes P2 (batching) valid. `u_lambda`/`u_eta` come from `self._u_lambda`/`self._u_eta`.

**C2 — `P_sym` is NOT constant across ADMM iterations.** This invalidates the "one Cholesky per tick" design in earlier drafts. `self._rho_scale = 3.0` (`:194`) is the **live, reference-conformant** path (ref `c3.cc:389-390`), applied at the end of *every* ADMM iteration (`:2242-2251`):

```python
_delta_rho = rho * (_rs - 1.0)
rho   *= _rs                    # rho *= 3 EVERY iteration
omega /= _rs                    # omega /= 3
np.fill_diagonal(P_sym, P_sym.diagonal() + 2.0 * _delta_rho * g_diag)   # G-on
```

The comment at `:187-194` is explicit that this replaced the "dead adaptive-rho every 10 iters branch." **Consequence:** the KKT matrix changes on every iteration — but only on its **diagonal**. So P3 (factor-once) still applies, one level down: factor per C3+ iteration, reuse across the ~100–2000 inner OSQP iterations. That is where the iteration count lives, so the reuse win survives.

**C3 — The delta-update is trivially vectorizable.** At `:1804-1860` it is `delta = z_sol + omega` (x and u pass through untouched), then lambda/eta blocks overwritten per knot. The per-knot Python loop exists only to feed a histogram.

**C4 — An ungated diagnostic loop sits in the hot path.** Inside that delta-update, `for _j in range(n_lambda)` (`:1832-1849`) recomputes, in pure Python scalar code, the case classification `_project_C3Plus` just computed vectorized. It is **not** behind any env gate. It feeds `_last_proj_case_hist`, consumed only by the `[CONSENSUS]` emission, itself gated to one solve per run. Cost: `N x n_lambda` Python iterations per ADMM iteration per sample — order 10x24x3x6 ~ 4300 scalar loop iterations per control tick, discarded.

**Other confirmed facts.** `_solve_c3plus` returns `(u_seq, x_seq)` — a 2-tuple (`:2957`); lambda is exposed via solver attributes, not the return. OSQP options (`:120-140`): `eps_abs = eps_rel = 1e-5`, `max_iter` 2000, `check_termination` 100, `scaling` 1 (Ruiz), `adaptive_rho` 1, `polishing` 0, `warm_starting` 1, `rho` 0.1, `sigma` 1e-5, `alpha` 1.6. Dimensions: `n_x=19`, `n_u=3`, `N=10` (box/T canonical; 7 and 5 exist for other lineages), `n_lambda = E.shape[0]` = 6*n_c under Stewart-Trinkle, `TOT = n_x + 2*n_lambda + n_u`, `total_dim = N*TOT + n_x` ~ 719 for n_c=4.

## Part 4 — Hardware reality check (read before writing any solver code)

Verified on this machine: **RTX 5070 Ti**, 16 GB, sm_120, driver 580.88; **Ryzen 7 7800X3D**, 8 cores / 16 threads. Neither torch nor cupy is installed.

**The fp64 problem.** GeForce Blackwell runs float64 at **1/64** the float32 rate. RTX 5070 Ti is ~44 TFLOPS fp32, so **~0.7 TFLOPS fp64**. A Zen 4 desktop CPU with AVX-512 has a theoretical fp64 peak of the same order (~1 TFLOPS). **This GPU has essentially no raw fp64 advantage over this CPU.**

The speedup therefore cannot come from out-FLOPping the CPU. It has to come from the three places the current implementation leaves order-of-magnitude factors on the table:

1. **The baseline is single-threaded** and pays Python plus Drake `MathematicalProgram` overhead on each of the ~18–25 QP solves per tick.
2. **Sparse LDL' on a dense-ish 719x719 problem** is overhead-dominated; batched dense Cholesky runs near peak.
3. **Six samples are solved one at a time**, so every BLAS call is at its least efficient size.

That is a real argument for batching, but it is an argument about **overhead elimination**, not FLOPs — and it must be *measured before it is built*. Hence Task 1 is a decision gate, not a setup step.

**The competing lever, stated plainly.** `evaluate_samples` (`control/sampling_c3/inner_solve.py:1216+`) *already has* a `ThreadPoolExecutor` path mirroring the reference's `#pragma omp parallel for num_threads(num_threads_to_use_)`. The port ships `num_threads_to_use = 1`; the reference ships `num_outer_threads: 4`. On a 16-thread CPU, raising that is a **config change** that parallelizes exactly the axis this GPU plan targets, and it is already the open item in `memory/project_admm_perf_psd_check_2026-08-20.md`.

This is not a reason to skip the GPU work — it has the higher ceiling and it is what was asked for. But the plan measures the thread lever **first** (Task 3) so the GPU is benchmarked against `threads=4`, not against an artificially serial baseline. Reporting a "5x GPU speedup" that is really "4x from threads we could have had for free" would be a false result.

```python
"""Decide whether fp64 batched dense linear algebra on THIS GPU beats this
CPU at OUR problem size. Run before writing any solver code."""
import time

import numpy as np
import torch

N_TOT, BATCH, REPS = 719, 6, 50   # total_dim ~719, 5-6 samples per tick


def _bench(fn, reps=REPS):
    fn()
    if torch.cuda.is_available():
        torch.cuda.synchronize()
    t0 = time.perf_counter()
    for _ in range(reps):
        fn()
    if torch.cuda.is_available():
        torch.cuda.synchronize()
    return (time.perf_counter() - t0) / reps * 1e3   # ms


def main():
    assert torch.cuda.is_available(), "CUDA not visible"
    print(torch.__version__, torch.cuda.get_device_name(0))
    M = np.random.default_rng(0).standard_normal((BATCH, N_TOT, N_TOT))
    K_np = M @ M.transpose(0, 2, 1) + N_TOT * np.eye(N_TOT)
    b_np = np.random.default_rng(1).standard_normal((BATCH, N_TOT, 1))

    K_g = torch.as_tensor(K_np, dtype=torch.float64, device="cuda")
    b_g = torch.as_tensor(b_np, dtype=torch.float64, device="cuda")
    K_c = torch.as_tensor(K_np, dtype=torch.float64)
    b_c = torch.as_tensor(b_np, dtype=torch.float64)

    gpu_chol = _bench(lambda: torch.linalg.cholesky(K_g))
    cpu_chol = _bench(lambda: torch.linalg.cholesky(K_c))
    L_g, L_c = torch.linalg.cholesky(K_g), torch.linalg.cholesky(K_c)
    gpu_slv = _bench(lambda: torch.cholesky_solve(b_g, L_g))
    cpu_slv = _bench(lambda: torch.cholesky_solve(b_c, L_c))

    print(f"batch={BATCH} n={N_TOT} fp64")
    print(f"  cholesky  : GPU {gpu_chol:7.3f} ms | CPU {cpu_chol:7.3f} ms"
          f" | speedup {cpu_chol / gpu_chol:5.2f}x")
    print(f"  chol_solve: GPU {gpu_slv:7.3f} ms | CPU {cpu_slv:7.3f} ms"
          f" | speedup {cpu_slv / gpu_slv:5.2f}x")
    K32, b32 = K_g.float(), b_g.float()
    f32 = _bench(lambda: torch.cholesky_solve(b32, torch.linalg.cholesky(K32)))
    print(f"  fp32 factor+solve: GPU {f32:7.3f} ms"
          f" (fp64 equivalent {gpu_chol + gpu_slv:7.3f} ms)")


if __name__ == "__main__":
    main()
```

"""Bui 2026 eq.(12) componentwise projection, batched (cuNRTO P5).

Exact torch transcription of C3Solver._project_C3Plus
(control/admm_solver.py:1035). That function is the specification.
Elementwise over any trailing shape -> valid to batch (cuNRTO P2).
"""
from __future__ import annotations

import math

import torch


def project_C3Plus_batch(lam: torch.Tensor, eta: torch.Tensor,
                         u_lambda: float = 1.0, u_eta: float = 1.0):
    sqrt_ratio = math.sqrt(u_lambda / u_eta)
    cond1 = (eta >= 0.0) & (eta >= sqrt_ratio * lam)
    cond2 = (lam >= 0.0) & (eta < sqrt_ratio * lam)
    zero = torch.zeros((), dtype=lam.dtype, device=lam.device)
    return torch.where(cond2, lam, zero), torch.where(cond1, eta, zero)

"""Batched dense OSQP iteration in torch (cuNRTO P1/P3/P6).

B independent QPs sharing shapes:  min 1/2 z'Pz + q'z  s.t.  l <= Az <= u.
Reduced KKT prefactored with batched Cholesky; only the RHS changes across
inner iterations (cuNRTO SM VIII-B). float64. Every iterate stays on-device;
solve() returns device tensors so the caller's loop never touches the host.
"""
from __future__ import annotations

import torch

_F64 = torch.float64


class BatchedBoxQP:
    def __init__(self, P, A, lo, hi, n_eq_rows, sigma=1e-5, rho_bar=0.1,
                 alpha=1.6, device="cuda"):
        self.dev = torch.device(device)
        kw = dict(dtype=_F64, device=self.dev)
        self.P = torch.as_tensor(P, **kw)
        self.A = torch.as_tensor(A, **kw)
        self.At = self.A.transpose(1, 2).contiguous()
        self.lo = torch.as_tensor(lo, **kw)
        self.hi = torch.as_tensor(hi, **kw)
        _, m, n = self.A.shape
        self.n, self.m, self.alpha, self.sigma = n, m, alpha, sigma
        rho = torch.full((m,), rho_bar, **kw)
        rho[:n_eq_rows] = 1e3 * rho_bar          # OSQP equality-row rho
        self.rho, self.rho_inv = rho, 1.0 / rho
        self.eye = torch.eye(n, **kw)
        self._factor(self.P)

    def _factor(self, P):
        self.L = torch.linalg.cholesky(
            P + self.sigma * self.eye
            + self.At @ (self.rho[:, None] * self.A))

    def refactor_diag(self, diag_delta):
        """C2: rho_scale ramps P by a DIAGONAL delta each C3+ iteration."""
        self.P = self.P + torch.diag_embed(diag_delta)
        self._factor(self.P)

    def solve(self, q, max_iter=2000, eps=1e-5, x0=None, z0=None, y0=None):
        kw = dict(dtype=_F64, device=self.dev)
        q = torch.as_tensor(q, **kw)
        B = q.shape[0]
        x = torch.zeros(B, self.n, **kw) if x0 is None else x0.clone()
        z = torch.zeros(B, self.m, **kw) if z0 is None else z0.clone()
        y = torch.zeros(B, self.m, **kw) if y0 is None else y0.clone()
        for it in range(max_iter):
            rhs = self.sigma * x - q + torch.bmm(
                self.At, (self.rho * z - y).unsqueeze(-1)).squeeze(-1)
            xt = torch.cholesky_solve(rhs.unsqueeze(-1), self.L).squeeze(-1)
            zt = torch.bmm(self.A, xt.unsqueeze(-1)).squeeze(-1)
            x = self.alpha * xt + (1.0 - self.alpha) * x
            z_prev = z
            z = torch.clamp(
                self.alpha * zt + (1.0 - self.alpha) * z_prev
                + self.rho_inv * y, self.lo, self.hi)
            y = y + self.rho * (
                self.alpha * zt + (1.0 - self.alpha) * z_prev - z)
            if (it + 1) % 100 == 0:            # OSQP check_termination = 100
                Ax = torch.bmm(self.A, x.unsqueeze(-1)).squeeze(-1)
                r_p = (Ax - z).abs().amax()
                r_d = (torch.bmm(self.P, x.unsqueeze(-1)).squeeze(-1) + q
                       + torch.bmm(self.At, y.unsqueeze(-1)).squeeze(-1)
                       ).abs().amax()
                if float(torch.maximum(r_p, r_d)) < eps:
                    break
        return x, z, y
```

"""Batched C3+ ADMM, fully on-device (cuNRTO P1/P2/P4).

Group instances by (N, n_lambda) before batching -- contact count varies
per sample, so shapes differ across groups.
"""
from __future__ import annotations

import numpy as np
import torch

from control.admm_solver import _assemble_c3plus_qp     # Task 5, shared
from .batched_qp import BatchedBoxQP
from .projection import project_C3Plus_batch

_F64 = torch.float64


class BatchedC3PlusSolver:
    @classmethod
    def from_instances(cls, instances, rho, u_lambda=1.0, u_eta=1.0,
                       rho_scale=3.0, device="cuda"):
        self = cls.__new__(cls)
        data = [_assemble_c3plus_qp(**a, rho=rho) for a in instances]
        d0 = data[0]
        for d in data[1:]:
            assert (d.N, d.n_lambda) == (d0.N, d0.n_lambda), \
                "group instances by (N, n_lambda) before batching"
        self.d0, self.dev = d0, torch.device(device)
        self.rho, self.rho_scale = rho, rho_scale
        self.u_lambda, self.u_eta = u_lambda, u_eta
        self.admm_iter = int(instances[0]["admm_iter"])
        kw = dict(dtype=_F64, device=self.dev)

        P = torch.as_tensor(np.stack([d.P for d in data]), **kw)
        self.q_ref = torch.as_tensor(np.stack([d.q_ref for d in data]), **kw)
        self.g = torch.as_tensor(np.stack([d.g_diag for d in data]), **kw)
        self.use_g = d0.use_g
        self.x0 = torch.as_tensor(
            np.stack([a["x0"] for a in instances]), **kw)

        # P_sym = 0.5*(P_tot + P_tot') + 1e-8 I, per _solve_c3plus
        aug = (2.0 * rho * self.g) if d0.use_g else rho * torch.ones_like(self.g)
        P_tot = P + torch.diag_embed(aug)
        eye = torch.eye(d0.total_dim, **kw)
        P_sym = 0.5 * (P_tot + P_tot.transpose(1, 2)) + 1e-8 * eye

        # A = [C_eq ; box selector rows];  equality rows have lo == hi == b_eq
        C_eq = torch.as_tensor(np.stack([d.C_eq for d in data]), **kw)
        b_eq = torch.as_tensor(np.stack([d.b_eq for d in data]), **kw)
        n_box = d0.box_idx.size
        sel = torch.zeros(len(data), n_box, d0.total_dim, **kw)
        bi = torch.as_tensor(d0.box_idx, dtype=torch.long, device=self.dev)
        sel[:, torch.arange(n_box, device=self.dev), bi] = 1.0
        A = torch.cat([C_eq, sel], dim=1)
        lo = torch.as_tensor(np.stack([d.box_lo for d in data]), **kw)
        hi = torch.as_tensor(np.stack([d.box_hi for d in data]), **kw)
        self.qp = BatchedBoxQP(P_sym, A,
                               torch.cat([b_eq, lo], 1),
                               torch.cat([b_eq, hi], 1),
                               n_eq_rows=C_eq.shape[1], device=device)
        return self

    def solve(self):
        d, kw = self.d0, dict(dtype=_F64, device=self.dev)
        B, N, TOT, n_x = self.x0.shape[0], d.N, d.TOT, d.n_x
        nl, n_u = d.n_lambda, d.n_u
        rho = self.rho

        delta = torch.zeros(B, d.total_dim, **kw)
        for i in range(N + 1):                       # delta_option = 1
            base = i * TOT if i < N else N * TOT
            delta[:, base:base + n_x] = self.x0
        omega = torch.zeros(B, d.total_dim, **kw)
        x = z = y = None

        for _ in range(self.admm_iter):
            if self.use_g:
                q_tot = self.q_ref - 2.0 * rho * self.g * (delta - omega)
            else:
                q_tot = self.q_ref - rho * (delta - omega)
            x, z, y = self.qp.solve(q_tot, x0=x, z0=z, y0=y)   # P6 warm start

            delta = x + omega                        # x and u pass through
            if nl > 0:
                zk = x[:, :N * TOT].reshape(B, N, TOT)
                wk = omega[:, :N * TOT].reshape(B, N, TOT)
                dk = delta[:, :N * TOT].reshape(B, N, TOT).clone()
                lam = zk[:, :, n_x:n_x + nl] + wk[:, :, n_x:n_x + nl]
                eta = zk[:, :, n_x + nl + n_u:] + wk[:, :, n_x + nl + n_u:]
                d_lam, d_eta = project_C3Plus_batch(
                    lam, eta, self.u_lambda, self.u_eta)
                dk[:, :, n_x:n_x + nl] = d_lam
                dk[:, :, n_x + nl + n_u:] = d_eta
                delta = torch.cat([dk.reshape(B, -1), delta[:, N * TOT:]], 1)
            omega = omega + x - delta

            # C2: reference rho_scale ramp (c3.cc:389-390), EVERY iteration
            if self.rho_scale > 1.0 and rho * self.rho_scale < 1e6:
                d_rho = rho * (self.rho_scale - 1.0)
                rho *= self.rho_scale
                omega /= self.rho_scale
                self.qp.refactor_diag(
                    2.0 * d_rho * self.g if self.use_g
                    else d_rho * torch.ones_like(self.g))

        zk = x[:, :N * TOT].reshape(B, N, TOT)
        u_seq = zk[:, :, n_x + nl:n_x + nl + n_u].cpu().numpy()
        x_seq = torch.cat(
            [zk[:, :, :n_x], x[:, None, N * TOT:N * TOT + n_x]], 1).cpu().numpy()
        return u_seq, x_seq
```

## Out of scope (YAGNI)

- **Custom CUDA kernels, cuDSS, PCG** — cuNRTO's PCG branch exists for its feedback-gain block (`O(T*n_u*n_x)`, 2940 vars on the Franka, matrix-free to avoid a dense Hessian). **C3+ has no feedback-gain block** — we are not solving a robust/tube problem — so that branch has no analogue here. Our KKT is dense and ~719; batched dense Cholesky is one cuSOLVER call across the batch.
- **Reproducing OSQP exactly** — bit-for-bit agreement would need Ruiz equilibration, internal adaptive-rho, and scaled termination ported too. Since OSQP itself stops at `eps=1e-5`, agreement is bounded there anyway; the acceptance bar is tolerance-based (Task 9) plus the two-tier sim eval (Task 14).
- **§7.67 B1-A (`PORT_G_WEIGHT_EE_BOX_FINAL`), the adaptive-rho >=10-iter branch, Lorentz C3 (`mode='c3'`)** — CPU fallback.
- **GPU-side LCS linearization** — Drake autodiff stays on host, exactly as cuNRTO keeps successive linearization on host (Fig. 2, Fig. 5).
- **jack task** — validate box and T first; jack adds per-task scales, not new solver structure.
